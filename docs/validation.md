# 验证记录与限制

## 2026-10-25 的初始个案

以下是一位使用者的环境与反馈，不是多地区统计样本：

- 德国，SIM 卡插入 CPE，电脑通过网线上网，使用者表示未开代理。
- 普通投稿视频正常，多个直播间无法播放，最初显示 `92002`。
- 使用者尝试无痕窗口及播放器的主线、备线后，反馈仍无法播放。
- 从同一电脑读取公开直播播放地址接口成功，部分默认媒体服务器连接超时。
- 在该次检查中，`cn-gotcha204` 的 AVC 与 HEVC fMP4 播放列表返回 HTTP 200；各读取少量媒体样本返回 HTTP 206。
- 加入备用节点的 0.2.0 版本安装后，使用者明确反馈可以播放。

故障发生期间，不同时间的接口分配结果也有变化。这里只记录检查到的现象，不将特定服务器判定为永久故障。

## 不应混为一谈的两次错误

最初的 `92002` 出现在没有使用此修复脚本时。未公开试验版 0.1.0 强制选择 TS 后，出现 `92006`。后者是该试验方案带来的兼容性问题，不能作为原始故障的佐证。

0.2.0 撤回格式强制选择，保留原始播放选项，仅加入 fMP4 备用节点。0.2.1 的修复逻辑与 0.2.0 相同。

## 自动检查能证明什么？

测试使用合成播放信息，覆盖：

1. 原格式、编码、画质、路径、签名和原服务器全部保留。
2. 只对匹配的 fMP4 候选列表加入备用节点。
3. Fetch 字符串与 Request 对象、XHR 文本与 JSON 响应。
4. 请求参数、身份凭据选项和取消信号透传。
5. 页面预载信息、重复处理、XHR 对象复用。
6. 业务错误、HTTP 错误、非 JSON、无目标节点和其他网站保持原行为。

这些检查验证数据处理逻辑，不能证明真实播放器会选择该节点或持续播放。

## 尚未验证

- 其他国家、运营商、设备及全部浏览器版本。
- 所有直播间、编码、画质、直播持续时长及跨时段可用性。
- 与其他改写播放地址脚本同时启用时的行为。
- 未来 B站接口、签名规则或 CDN 调度变化后的兼容性。

独立自动化浏览器访问真实直播页面时曾遇到验证码，因此没有把自动化测试记为完整真实直播端到端验证。成功播放的证据来自使用者反馈。

## 如何补充有效反馈？

使用问题模板，记录大致国家/网络类型、浏览器、脚本版本、报错、左下角状态，以及关闭脚本后的对比。多次试播和持续播放时长能帮助判断稳定性。

不要上传 Cookie、授权头、完整签名媒体地址、账号截图或未经脱敏的 HAR/网络日志。
